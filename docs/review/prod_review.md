# VolatilityViking - Production Readiness Review (non-strategy)

Scope: read-only. Live path = `main.py:98-100` -> `src/live/async_runner.py:main_async` (spot, ccxt async, Binance). `src/live/binance_bot.py` is the legacy sync bot (only reachable via `python src/live/binance_bot.py`, documented in DOCKER_RUN_GUIDE.md:54,66 and HOW_TO_GUIDE.md:34-74).

## 0. Headline blockers (fix before real money)

1. **Kill switch is defeated by the restart policy.** `async_runner.py:994-998` sets stop_signal and breaks -> process exits 0. Docs mandate `--restart unless-stopped` (DOCKER_RUN_GUIDE.md:25,119), which restarts on exit 0. `peak_equity` (`:67`) and `kill_switch_active` (`:69`) live only in memory, so the restarted bot starts with peak=0 and trades again. Same in legacy bot (`binance_bot.py:172-173`, `sys.exit(1)` at `:397`). Kill switch also only cancels orders (using the stale `self.open_orders` cache, `:259`), never flattens the position.
2. **Kill switch false-trigger paths.** Equity = USDT + sum over *currently configured* symbols only (`:163-183`). (a) Forager de-selects/hot-reload removes a symbol while held -> equity drops by its value -> drawdown -> kill. (b) Operator withdraws profit -> "drawdown". (c) BNB/other balances ignored. (d) Symbol never priced (price 0, `:171-172`) counts as 0. No deposit/withdrawal adjustment.
3. **Clean clone cannot build or run.** `.gitignore:12,16` (`data/`, `models/`) also ignores `src/data/` and `src/models/` -> `git ls-files` has neither. `binance_bot.py:15,20`, `portfolio_manager.py:15`, `main.py:31` import `src.data.news_fetcher` / `src.models.*`. `Dockerfile:36` does `COPY data/raw/` (gitignored dir) -> build fails on a fresh checkout. `Dockerfile` never copies `config.json` or `tools/`.
4. **Missing/invalid config silently degrades.** `load_config` (`async_runner.py:75-81`) returns `{}` on any error. At startup that means `live_mode=False` -> testnet with empty creds (`:85-105`); at hot-reload (`:923-926`) a half-saved config.json replaces the running live config with `{}` (defaults: ETH/USDT only, `grid_span` 0.30 vs 0.006 in file, forager off, WEL 1.0). `tools/allocate_capital.py` / `momentum_allocator.py:144-147` also rewrites config.json (atomic replace, good) while the bot hot-reloads it.
5. **Committed config is live.** `config.json:6 "live_mode": true`. No explicit confirmation flag, no env-level guard.
6. **Zero alerting, zero heartbeat, zero order audit log in the live path.** grep for telegram/discord/slack/pagerduty/prometheus/sentry/healthcheck: no hits in code.
7. **Failed open-order fetch => duplicate grid.** `fetch_all_orders` returns `[]` on exception (`:326-327`); `process_symbol` then sees no orders and places a full new grid on top of existing ones (`:~790-805`). No `newClientOrderId` anywhere (grep) -> no idempotency.

## 1. Failure-mode table

| Failure | Current behaviour (cite) | Desired |
|---|---|---|
| Exchange API down / 5xx | Every call wrapped in broad `except Exception` -> log + continue; ticker failure keeps stale `last_prices` (`:137-139,144-146`); positions keep stale values (`:195-197`); OHLCV failure silent (`:340-341`, no log) so indicators go stale forever; loop retries every 5s (`:1030`) with no backoff/staleness check; orders fetch failure -> `[]` (see #7). | Per-cycle health object: if any of price/balance/orders fetch fails or data age > N s, skip order placement for that cycle (cancel nothing). Exponential backoff w/ jitter. Alert after N consecutive failed cycles. |
| 429 / 418 ban | Not distinguished. ccxt `RateLimitExceeded`/`DDoSProtection` caught by generic handlers; loop keeps firing ~(2N+1) REST calls/5s plus an extra `fetch_balance` (weight 20) before *every* order (`:~482`). Hammering during a 418 extends the ban (2 min -> up to 3 days). | Catch `RateLimitExceeded`/`DDoSProtection`; parse Retry-After / ban-until timestamp; pause all REST until then; alert. Drop per-order balance refresh; use websocket user-stream or refresh once per cycle. |
| Network partition | Same as API down; resting limit orders stay on exchange and can fill unattended; no timeout config beyond ccxt default. | Set explicit ccxt `timeout`; alert when partition > 2 min; accept resting grid risk (spot, no leverage) but record `last_ok_ts`. |
| Clock skew | No `adjustForTimeDifference`/`recvWindow` (grep none). -1021 errors are just logged each cycle. | `adjustForTimeDifference: True`, `recvWindow` 10-15s; startup NTP check (chrony) and fail-fast if skew > 1s; alert on -1021. |
| Process crash (unhandled exception) | Only `run()` has try/finally (`:955-1036`); per-symbol errors swallowed. Unhandled exception in loop outside gather (e.g. config reload edge, `check_kill_switch` math) -> exit, Docker restarts; state lost (peak_equity, trailing HWM `:59`, `_balance_warned`). Open orders re-read from exchange (good). | Crash -> restart is acceptable *only if* peak equity, kill-switch latch, and trailing state are persisted (SQLite) and reloaded. Alert on restart count. |
| Container restart / `docker stop` (SIGTERM) | No signal handler (grep `signal` none in async_runner/main). Python as PID 1 ignores SIGTERM w/o handler -> 10s then SIGKILL; `finally` (`:1034-1036`) never runs; ccxt session not closed. No `init: true`/tini. | `loop.add_signal_handler(SIGTERM/SIGINT)` sets stop flag, finishes cycle, closes exchange, logs final state. Do NOT cancel orders on SIGTERM for a passive grid (decide explicitly; document). `docker run --init`, `--stop-timeout 30`. |
| VM reboot | Docker `unless-stopped` brings container back if docker enabled; `setup_vm.sh` installs no service; legacy `nohup` (HOW_TO_GUIDE.md:74) dies. Same state-loss as crash; startup has no reconciliation or alert "I restarted". | systemd unit (or compose) with `Restart=always`, state in volume, startup reconciliation + Telegram "bot started, equity X, peak Y, open orders N". |
| Disk full | Log FileHandler errors are swallowed by logging (`handleError` prints to stderr) -> bot keeps trading blind; no rotation: new `logs/async_bot_<ts>.log` per start (`async_runner.py:17-27`, created at *import time*), unbounded growth; Docker json-file logs also unbounded (no `--log-opt`). binance_bot CSV append can raise -> caught by loop `:1670s`. | `RotatingFileHandler`/journald, docker `--log-opt max-size=10m max-file=5`, disk-free check in heartbeat, alert at 80%. |
| Bad config | See blocker #4. No schema validation; `.get()` defaults differ from shipped file (e.g. `grid_span` 0.30 vs 0.006 at `:615`, `qty_step_multiplier` 1.4 vs 1.25 `:617`), so a typo silently changes risk. `total_wallet_exposure_limit: 1.5` (config.json:11) is meaningless on spot (cannot exceed 1.0). `max_drawdown_pct` is read once (`:68`) so hot-reload doesn't apply it. | Pydantic/jsonschema validation at start and on reload; reject invalid reload and keep last-good config + alert; bounds checks (WEL<=1 for spot, drawdown 0<x<1); `--check-config` dry-run command; no defaults for risk params (must be explicit). |
| Insufficient balance | `place_limit_order` catches, warns once per symbol *ever* (`:502-506`, set never cleared) then silent forever; exposure check uses stale equity. | Rate-limited warn (e.g. once per hour), counter metric, alert if persistent > 1h (capital idle / stuck). |
| Exchange maintenance | Binance returns -1013/-2010/503 or `ExchangeNotAvailable`; treated as generic errors -> retries every 5s. `_markets` cached once forever (`:293-294`), never refreshed (filters/status changes). | Detect `ExchangeNotAvailable`/system status endpoint, enter PAUSED state with backoff, alert; refresh markets every few hours. |
| Delisting / market halt | `fetch_ticker` raises each 5s (logged as ERROR); last good price remains in `last_prices` so equity uses a stale, wrong price; position never exited; forager may keep selecting it. No `market['active']` check. | Check `market['active']`; on delist notice/BadSymbol N times -> alert, mark symbol DISABLED, cancel its orders, exclude from equity or use last-trade valuation with flag. Subscribe to Binance delisting announcements manually. |
| API key revoked / IP-ban / permission change | No startup auth check (`init_exchange` `:83-105` doesn't verify keys; missing key -> `None` passed to ccxt). `AuthenticationError` swallowed and retried forever every 5s. With revoked key, resting orders remain live with no control. | Fail-fast at startup: required env present, `fetch_balance` + `fetch_open_orders` succeeds, permissions via `GET /sapi/v1/account/apiRestrictions` (assert enableWithdrawals == False, enableSpotAndMarginTrading True). At runtime: `AuthenticationError`/`PermissionDenied` -> critical alert, stop loop (exit non-zero, restart policy `on-failure` with limit). |
| Kill switch triggered | See blockers #1-2. | Persistent latch in DB/file: on trigger cancel orders (fresh fetch), optionally market-sell to USDT, alert, **idle (not exit)** until operator clears latch. |

## 2. Security

- **Key permissions**: nothing in repo/docs says enable-trade-only, withdrawals disabled, IP whitelist. DOCKER_RUN_GUIDE.md:199-201 mentions "read-only keys for dashboard", but `dashboard.py:32-34` reads the same `BINANCE_API_KEY`/`BINANCE_SECRET_KEY` as the trader and no separate `BINANCE_RO_*` var exists. Recommend: trade key = Spot trading only, withdrawals OFF, universal transfer OFF, IP-restricted to VM static IP; separate read-only key for dashboard/monitor; startup assert via `apiRestrictions`. Use a sub-account holding only the bot capital.
- **Secrets handling**:
  - `main.py:70` `load_dotenv(args.env_file, override=True)` lets a stray `.env` override orchestrator-injected secrets/env (surprise live vs testnet switching). Use `override=False`.
  - `.env` missing is silent (load_dotenv returns False, unchecked).
  - `check_creds.py:20,24` prints first4...last4 of BOTH key and secret into terminal/scrollback/CI logs. Never print any part of the secret; print only key fingerprint (sha256 prefix).
  - `scripts/check_balance.py` is testnet-only, does not leak keys; prints balances (fine). No live-key variant.
  - DOCKER_RUN_GUIDE.md:181,185 instructs `docker exec ... env | grep BINANCE` and `cat .env` (secrets in terminal/history); `--env-file` puts secrets in `docker inspect`. Prefer Docker/compose secrets or systemd `LoadCredential`/`EnvironmentFile` with 0600 root-owned file.
  - `.dockerignore:11` excludes `.env` (good) but `.env_riz` (personal env, referenced `.gitignore:27`, `dashboard.py:18`) is not excluded; Dockerfile copies selectively so currently safe.
  - No secrets found in git history grep (checked file names + key-pattern grep). Run gitleaks in CI anyway.
  - Logging: error strings are `logger.error(f"...{e}")` with raw ccxt exceptions; ccxt includes URL/response body, signed query strings (timestamp+signature, not key) - low risk but add a redaction filter for `signature=`, key, secret.
  - `scripts/migrate_to_cloud.sh:5,14` commits a real username and public IP; rsync does NOT exclude `.env` (lines 8-12), so it copies live secrets to the VM with whatever perms; no `set -e`, prints "Finished" regardless of rsync exit; source path `<hard-coded home path>` hard-coded; no `--dry-run`, no backup of remote config.json/data.
- **Dashboard exposure**: `dashboard.py` has no auth; Docker guide publishes `-p 8501:8501` (DOCKER_RUN_GUIDE.md:76,101) on a VM IP over plain HTTP, showing balance/trade history; guide only says "firewall port 8501" (:201). Bind to 127.0.0.1 and use SSH tunnel / Tailscale; or Caddy+basic auth.
- **Container**: runs as root (no `USER`, Dockerfile), no `HEALTHCHECK`, base `python:3.10-slim` unpinned by digest (Python 3.10 EOL Oct 2026 - today is Nov 2026, i.e. already EOL), apt gcc/g++/git/curl left in final image (no multi-stage), `EXPOSE 8501` on the bot image.
- **Dependency pinning / supply chain**: `requirements.txt` has zero pins except `numpy<2.0.0` (`:4`); includes `web3`, `yfinance`, `streamlit`, `mlflow`, `sentence-transformers`, `torch`, `numba` - huge attack surface and cold-build non-reproducibility for a bot whose live path needs only `ccxt pandas numpy python-dotenv` (+ `main.py:6` imports `mlflow` at top-level, forcing the heavy dependency even for live; move import inside `run_pipeline`). Dockerfile strips torch with `grep -v "torch"` (`:25`), which also strips any other package whose name contains "torch"; `pip install ... sentence-transformers requests streamlit plotly` (`:29`) again unpinned. Torch installed from external index URL. No lockfile/hashes, no Dependabot/CI (no `.github`). ccxt unpinned is the riskiest: exchange-API behaviour changes between versions. Recommendation: `pip-compile --generate-hashes` (or uv lock) and `pip install --require-hashes`; split `requirements-live.txt` / `requirements-research.txt`; pin ccxt exactly and upgrade deliberately; `pip-audit` in CI; image pinned by digest; sign/scan with trivy.
- Image distribution by `docker save` tarball (`DOCKER_RUN_GUIDE.md:7,210`; `.gitignore:23`) - no registry, no tags/digests, no provenance; "eth-bot:latest" everywhere -> no rollback target.

## 3. Operability

- **Alerting**: none. Nothing pages on kill switch, restart, auth failure, 418 ban, stuck state.
- **Heartbeat**: none. `tools/monitor.py` is a manual terminal script: checks log mtime >120s (`:42`) and greps last 200 lines for ERROR/WARNING (`:54-57`); always exits 0 (no usable exit code for cron/healthcheck); selects "latest log by ctime" (`:21`) which breaks with restart-generated files; only sees the process if it writes logs; cannot see equity/drawdown/open orders/kill state; relies on a regex of a log line format that is emitted only when `int(time.time())%60<5` (async_runner.py:910).
- **PnL reporting**: `dashboard.py` is reconstruction from exchange trades: `fetch_my_trades(symbol, since=30d, limit=1000)` (`:65-69`) returns the *oldest* 1000 trades since the window start, so a busy grid under-reports recent trades/PnL; exceptions swallowed with `pass` (`:81-82`); FIFO PnL ignores inventory held before the window (sells with empty inventory are dropped, `:117`), fees only counted when in USDT (`:110,114`; Binance spot fees are often in base asset/BNB), no unrealized PnL or equity curve/drawdown, only configured symbols (`:57`). Uses live trading keys. Streamlit on every refresh calls API (60s cache) - extra weight.
- **Audit trail**: live path (`async_runner.py`) writes **no** order/fill record besides a one-line INFO (`:495`, no order id, no fee, no params). Legacy bot has `data/logs/live_trades.csv` (`binance_bot.py:166-170`), not used by async runner. No cancel records, no decision context (price, anchor, ADX, WEL at decision time). `src/utils/db.py` is a SQLite prediction log only (used by `src/live/trader.py:6,46`, not by async runner): fresh connection per call, no WAL, no `timeout`, no schema versioning, relative path `data/predictions.db` (`:6`), `init_db()` prints, no indexes; not production persistence for orders/equity.
- **Structured logs**: plain text `'%(asctime)s [%(levelname)s] %(message)s'` (`:20-27`), local time (no TZ), emojis in messages, logging configured as an import side-effect at module import (creates `logs/` dir + file even under pytest). No JSON, no run id, no rotation. Legacy bot redirects `print()` into logging (`binance_bot.py:48-60`).
- **Metrics**: none (no Prometheus). Useful minimal set: loop_last_success_ts, equity, peak_equity, drawdown, free_usdt, open_orders{symbol}, exchange_errors_total{type}, orders_placed_total, fills_total, kill_switch_state, config_version, clock_skew_ms.
- **News APIs**: in the *async live path* there are **none** (async_runner imports: asyncio/ccxt/json/os/time/logging/dotenv/pandas/numpy; `PortfolioManager`/NewsFetcher imported lazily in `run_portfolio_manager_async` `:1039-1043` and `main_async` explicitly "bot only" `:1058-1063`). So CryptoPanic/CryptoCompare failing cannot affect the async bot. In the **legacy `binance_bot.py` they are hard dependencies**: `get_signal` aborts in "STRICT MODE" when news is empty (`:921-946` area) -> signal None -> `time.sleep(60); continue` (`:~1645-1648`) -> **grid maintenance never runs while the news API is down**; NewsFetcher source (`src/data/news_fetcher.py`) is not in the repo (gitignored), so I could not verify its timeouts/retries; `scripts/test_cryptopanic.py:12` shows `CRYPTOPANIC_API_KEY` env needed. `PortfolioManager` also calls news (`portfolio_manager.py:215-248`) with `except Exception` -> returns neutral presumably; weights news 0.10 (`:276`). Recommendation: delete the legacy bot or at minimum make news optional with timeout + circuit breaker; keep it out of the live image.
- **Doc/code drift**: `main.py:60-64` accepts `--symbol/--timeframe/--aggressive/--async-mode` but live mode ignores them (`:89-100` only uses `--config`); DOCKER_RUN_GUIDE.md "Aggressive mode"/"--symbol" examples (`:41,54,66`) therefore do nothing for `--mode live`; "Testnet" recipes run the legacy bot instead of the live bot; Docker `CMD` (`Dockerfile:50`) passes `--symbol ETH/USDT` that is ignored. Error message `main.py:81` mentions nonexistent `--dashboard`.

## 5. Target architecture (single operator, passive bot)

```
Binance (trade-only key, IP-whitelisted to VM, no withdrawal; separate RO key for reporting)
        ^ REST (ccxt, timeouts, backoff, ban-aware)
+-------|---------------- 1 small VM (2 vCPU/2-4GB, static IP, chrony) -----------------+
| docker compose (restart: unless-stopped, init: true, stop_grace_period: 30s,          |
|   logging: json-file max-size 10m x5, mem limit, read_only rootfs, non-root user)     |
|  bot       : python -m volatility_viking.live --config /etc/vv/config.live.yaml       |
|              slim image (ccxt,pandas,numpy,pydantic,prometheus_client), hash-pinned   |
|              /health (localhost) + heartbeat; SIGTERM handler                           |
|  reporter  : (optional) streamlit/CLI on 127.0.0.1, RO key, reads SQLite              |
|  state: /var/lib/vv/state.db (SQLite WAL, volume, nightly `.backup` to object storage) |
|     tables: orders(client_id, exch_id, ts, symbol, side, px, qty, status, ctx_json),  |
|             fills(trade_id, ...fee, fee_ccy), equity_snapshots(ts, equity, peak,     |
|             free_usdt), kv(peak_equity, kill_latch, config_hash, last_ok_ts), events  |
|  alerts: Telegram bot (token in secret) - critical/warn/info + daily digest           |
|  optional: node_exporter + bot /metrics -> Grafana Cloud / local Prometheus           |
+---------------------------------------------------------------------------------------+
External dead-man's switch: healthchecks.io ping every minute from bot loop
   (pages you by Telegram/email if pings stop => catches VM down, container wedged, partition)
```

Key design rules:
1. **Startup gates**: validate config (pydantic); required secrets present; clock skew < 1s; auth OK; `apiRestrictions.enableWithdrawals == False`; markets active; reconcile exchange open orders & balances vs DB; send "started" alert with equity/peak/config hash. Refuse live unless `LIVE_CONFIRM=<account-id>` env matches.
2. **Cycle discipline**: each cycle builds a snapshot (prices, balances, open orders, timestamps). If any component failed or is older than 15s -> no order actions. Mutations only via `OrderManager` using deterministic `newClientOrderId` (`vv-{symbol}-{side}-{level}-{epoch_bucket}`), writes intent to DB first, result after. Single in-flight guard per symbol.
3. **Error taxonomy**: transient (network/5xx) -> backoff; rate-limit/ban -> global pause until ban-end; auth/permission -> critical alert + stop; invalid-order -> per-symbol cooldown; maintenance -> PAUSED + periodic probe.
4. **Risk latches persisted**: peak equity (with deposit/withdraw adjustment via `fetch_deposits/withdrawals` or manual `vv adjust-peak` command), kill-switch latch, daily-loss limit. On trigger: cancel fresh-fetched orders, optional market-flatten, alert, **stay running idle** (heartbeat continues) until `vv reset-killswitch`. Equity valued over *all* non-dust balances, not config symbols.
5. **Shutdown**: SIGTERM -> finish cycle, flush DB, close ccxt, exit 0; compose policy `unless-stopped` is then safe because the latch is persisted.
6. **Observability**: JSON logs with run_id/symbol/order ids; daily Telegram digest (equity, realized PnL from DB fills, open orders, fees, drawdown); alert on: restart, kill, auth/ban, stale data > 2 min, no heartbeat, disk > 80%, balance idle > 1h, config reload rejected.
7. **Release process**: git tag -> CI (pytest, ruff, pip-audit, gitleaks, build with locked hashes) -> push image to GHCR by digest; compose pins `image@sha256:`; rollback = change digest + `docker compose up -d`. Separate `config.testnet.yaml` and `config.live.yaml`, config hash recorded in DB; live config changes via PR, applied by restart (or validated hot-reload that keeps last-good).
8. **Rollout**: testnet 7d -> sub-account at 5% -> 25% -> 100%, with a fire-drill at each stage (kill the container, revoke the key on testnet, block network, fill disk).
9. **Housekeeping**: remove/segregate legacy `binance_bot.py`, training stack, `portfolio_manager`/allocator from the live image; fix `.gitignore` to `/data/` and `/models/` (anchored) so `src/data` and `src/models` are tracked; drop `main.py` top-level `mlflow` import.
